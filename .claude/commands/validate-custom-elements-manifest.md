You are validating the component at `$ARGUMENTS` against the
**custom-elements-manifest** guideline. Be exhaustive and concrete —
file paths and line numbers, not vague summaries. Read-only: do not
edit any files in the target.

## Step 0 — Applicability gate (D-CEM-1)

This triad is **web-components only**. If the package has **no**
`customElements.define(...)` call in `src/`, it's a Svelte / light-DOM
component and the entire triad is **N/A** — report every check as N/A
with the reason and stop. The `.checks.sh` script performs this gate
automatically and skips everything.

Dual-build packages (a Svelte component that *also* ships a
`customElements.define(...)` custom-element build — D-CEM-1 = C) are
validated as web-components against the custom-element build's entry
points.

### Step 2.5 — Load accepted-deviation registers

Before evaluating any check, look for two files that record deviations
the team has already accepted. Their content downgrades matching
`❌ Fail` verdicts to `⚠️ Exception`.

- **`README.md` → `## Known limitations`** (consumer-facing).
- **`$ARGUMENTS/VALIDATION-NOTES.md`** (internal-only). One section per
  accepted deviation, headed with the check ID(s), e.g.:

  ```markdown
  ## C-CEM-2 — D-CEM-3 = B (separate generator scripts)
  The analyzer plugins are incompatible with our bundler; the editor
  files are generated by dedicated scripts that run under `build`.
  ```

Discipline: an entry that explains *why the deviation is correct*
downgrades the verdict. An entry that defers ("fix later", "todo")
stays a Fail. If neither file exists, proceed at face value.

## Step 4 — Run the semi / manual checks (judgment path)

For the four checks the script doesn't cover:

- **C-CEM-10** `[semi]` (manifest is fresh) — The definitive test is
  re-running `cem analyze` and diffing, which mutates the working tree,
  so mark ⚠️ Manual and give the exact steps: `npm run analyze` then
  `git diff --stat` on the three artifacts. As a read-only proxy, spot-
  check that the tag / an attribute you can see in `src` is present in
  `custom-elements.json`.
- **C-CEM-11** `[semi]` (manifest matches source) — Read
  `custom-elements.json`. Cross-reference the declared `tagName`
  against `customElements.define(...)` (must match C-CST-2 / C-NC-1),
  the declared `attributes[]` against the `ATTRIBUTE_TABLE` /
  `observedAttributes` (C-NC-7), and `events[]` against the
  `dispatchEvent` call sites (C-NC-3). Flag anything present in source
  but missing from the manifest (or vice-versa). The fix is JSDoc
  (`@attr` / `@fires`) on the Element class, never a hand-edit.
- **C-CEM-12** `[manual]` (editor autocomplete works) — Always ⚠️
  Manual. Give the exact steps: `npm pack`, install the tarball into a
  scratch folder, wire `html.customData` in `.vscode/settings.json`,
  and confirm tag + attribute completion in VS Code; open the same
  folder in WebStorm and confirm `web-types` auto-discovery.
- **C-CEM-13** `[semi]` (public-facing members carry harvestable JSDoc)
  — Find the public options interface (the type whose members are the
  `key:` targets in `ATTRIBUTE_TABLE`, e.g. `DatePickerOptions` in
  `src/types.ts`). For each backing member, confirm a `/** */` block
  precedes it — bare members and inline `//` comments both fail (the
  analyzer harvests neither). For enum / union members, confirm the
  canonical **intro line + blank line + bullet-per-value** shape from
  `custom-elements-manifest.md` → "Canonical property-JSDoc format".
  Grep smell test: `grep -nE "^\s*[A-Za-z_].*:.*//" src/types.ts` for
  trailing `//`, `grep -nE "^\s*//" src/types.ts` for standalone `//`.

If a check's bash snippet uses tools not available on Windows, use the
Read tool to load the relevant file and reason about it directly.

## Discipline

- Never mark ✅ without actually running the verification.
- If Step 0 gates the package out (no `customElements.define`), report
  every check N/A with the reason — don't invent failures.
- C-CEM-10 and C-CEM-12 are ⚠️ Manual unless you have permission to run
  `npm run analyze` / `npm pack` in the target (they mutate the tree /
  hit the registry).
- A documented N/A per a decision (D-CEM-1 = B, D-CEM-3 = B) is N/A
  with citation, not a failure.
- Prefer Grep over `Bash` + `grep`; prefer Read over `cat`. Run
  independent Grep/Read calls in parallel.
